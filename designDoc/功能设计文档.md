# AI 流式对话应用 - 功能设计文档

## 1. 项目概述

### 1.1 项目简介

本项目是一个基于 SSE（Server-Sent Events）技术的 AI 流式对话应用，支持智谱 AI 和讯飞星火双平台，提供实时流式输出、代码高亮、对话导出等功能。

### 1.2 技术栈

| 层级 | 技术选型 |
|------|----------|
| 前端 | React 18 + Vite + highlight.js |
| 后端 | Node.js (原生 http/https 模块) |
| 通信协议 | SSE (Server-Sent Events) |
| 代码高亮 | highlight.js |

#### 3.2.2 流式输出

**SSE 数据格式：**

```
data: {"content": "你", "usage": null}

data: {"content": "好", "usage": null}

data: {"content": "！", "usage": {"prompt_tokens": 10, "completion_tokens": 3}}

data: [DONE]
```

**前端处理流程：**

```javascript
// 1. 建立 SSE 连接
const response = await fetch('/api/chat', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'text/event-stream',  // 声明期望 SSE 格式
  },
  body: JSON.stringify({ apiKey, model, messages, stream: true })
});

// 2. 获取 ReadableStream 读取器
const reader = response.body.getReader();
const decoder = new TextDecoder();

// 3. 循环读取流式数据
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  // 4. 解码二进制数据为字符串
  const text = decoder.decode(value, { stream: true });
  
  // 5. 按 SSE 协议解析数据
  parseSSEData(text);
  
  // 6. 实时更新 UI
  updateMessageContent(content);
}
```

**连接中断感知：**

```javascript
try {
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    // 处理数据...
  }
} catch (error) {
  // 捕获连接中断错误
  if (partialContent) {
    // 保存已收到的部分内容
    savePartialMessage(partialContent + '\n\n⚠️ [连接中断]');
  }
  throw new Error('连接中断，请检查网络后重试');
}
```

#### 3.2.6 会话管理（结构与实现）

**功能说明：** 支持多会话并存，每个会话独立消息列表；会话列表与当前会话 ID 持久化到 localStorage，切换会话时从本地加载该会话消息并注入 useChat。

**数据结构：**

```typescript
// 会话完整数据（含消息，按 id 存 localStorage）
interface SessionData {
  id: string;
  title: string;
  messages: Message[];
  createdAt: number;
  updatedAt: number;
}

// 会话列表项（不含 messages，用于侧栏列表）
interface SessionMeta {
  id: string;
  title: string;
  createdAt: number;
  updatedAt: number;
}
```

**存储约定：**

- `chat_session_list`：`{ currentId: string; ids: string[] }`，当前会话 ID 与所有会话 ID 列表。
- `chat_session_{id}`：单会话 JSON（SessionData）。标题由首条用户消息前 28 字生成，可覆盖。

**实现要点：**

- **utils/sessionStorage.ts**：`getSessionList`、`getCurrentSessionId`、`setCurrentSessionId`、`getSession`、`saveSession`、`createSession`、`deleteSession`；删除当前会话时自动切到列表第一项或新建。
- **hooks/useSessions.ts**：维护 `sessions`（SessionMeta[]）、`currentSessionId`、`currentSessionData`；提供 `createSession`、`deleteSession`、`switchSession`、`saveCurrentSessionMessages`；切换会话时同步写回 localStorage 的 currentId。
- **useChat**：接收 `sessionId`、`initialMessages`；当 `sessionId` 变化时重置 `messages` 为 `initialMessages`，清空流式与错误状态。
- **App**：useSessions 与 useChat 桥接：把 `currentSessionId`、`currentSessionData?.messages` 作为 `sessionId`、`initialMessages` 传入 useChat；在非 requesting/streaming 时用 `saveCurrentSessionMessages(messages)` 写回当前会话。

#### 3.2.7 统一模型协议（结构与实现）

**目的：** UI 与 useChat 不直接调用 fetch/axios，只依赖「模型请求参数 + 回调」，便于以后换 SDK 或接口。

**类型定义（types/model.ts）：**

```typescript
interface ModelMessage {
  role: 'user' | 'assistant' | 'system';
  content: string;
}

interface ModelRequestParams {
  modelId: string;   // 格式 "provider:model"，如 "zhipu:glm-4.5-flash"
  messages: ModelMessage[];
  temperature?: number;
  maxTokens?: number;
  stream?: boolean;
}

interface ModelCallbacks {
  onChunk: (chunk: string) => void;      // 流式为累积全文，非流式为整段
  onComplete: (usage?: ModelUsage) => void;
  onError: (error: Error) => void;
}
```

**实现要点：**

- **services/modelService.ts**：唯一调用 chatService（进而调用 api/chat + fetch）的入口。`requestModel(params, callbacks, { signal, apiKey })` 内将 `modelId` 解析为 `provider`、`model`，组装 `ChatRequestParams`，流式走 `sendStream`、非流式走 `sendNonStream`，在 onChunk/onComplete/onError 里转调 callbacks。
- **useChat**：只调用 `requestModel`，传入 `modelId: \`${provider}:${model}\``、`messages`、`stream` 及 onChunk/onComplete/onError，不出现 fetch 或 api/chat。

#### 3.2.8 上下文是否包含 system 消息

**功能说明：** 可配置「发给模型的上下文」是否包含 role 为 system 的消息；用于在保留对话轮数不变的前提下排除 system 以节省 token 或满足平台限制。

**实现要点：**

- **useChat**：`includeSystemInContext` 默认 true。`contextMessages` 在过滤 user/assistant/system 后，若 `includeSystemInContext === false` 再过滤掉 system，再取最近 `contextLength * 2` 条。
- **Sidebar**：展示「上下文包含 system 消息」复选框，绑定 `includeSystemInContext`、`onIncludeSystemInContextChange`（来自 useLocalStorage）。

#### 3.2.9 消息列表虚拟化（长对话优化）

**功能说明：** 消息条数超过阈值（如 50）时，只渲染最近 N 条，并在列表顶部显示「上方还有 X 条消息，仅展示最近 N 条」，减轻 DOM 与 re-render。

**实现要点：**

- **MessageList**：接收 `virtualThreshold?: number`（0 表示不限制）。当 `messages.length > virtualThreshold > 0` 时，`visibleMessages = messages.slice(-virtualThreshold)`，`collapsedCount = messages.length - virtualThreshold`；渲染时先展示折叠提示再渲染 `visibleMessages`。
- **ChatContainer**：传入 `virtualThreshold={50}`（常量 `MESSAGE_VIRTUAL_THRESHOLD`），滚动仍由父级 messages-area 统一处理。

#### 3.2.10 Markdown 完整渲染（结构与实现）

**功能说明：** 消息正文除代码块外，支持标题、水平线、引用、表格、任务列表、无序/有序列表、段落；行内支持链接、图片（安全协议）、行内代码、粗体/斜体/删除线。

**实现结构（MessageContent.tsx）：**

1. **parseContent(text)**：用已闭合的 \`\`\`...\`\`\` 正则拆分为「普通文本」与「代码块」交替；仅闭合代码块交 CodeBlock 高亮，未闭合部分走 formatInlineText。
2. **formatInlineText(text)**：按行扫描，维护 blockquote/ul/ol/task/paragraph 缓冲区；遇到标题（# 1–6）、水平线（---/***/___）、表格行（|...|）、引用（> ）、任务列表（- [ ] / - [x]）、无序/有序列表时先 flush 再切换；最后统一 flush。
3. **表格**：`parseTableLines` 解析表头与分隔行后的数据行，`splitTableRow` 按 | 分割单元格，输出 `<table><thead>/<tbody>`。
4. **行内 formatLine(line)**：先用 \`...\` 切段，段内再解析链接、图片、粗体/斜体/删除线（parseSegmentWithLinks → formatInlineBoldItalic）；链接与图片仅允许 http(s)/、/、#、mailto:，避免 javascript:。
5. **CodeBlock**：仅接收已闭合代码块，highlight.js 高亮 + 复制按钮；异常时回退纯文本。

## 4. API 设计

### 4.1 后端 API 接口

#### POST /api/chat

AI 对话代理接口，转发请求到对应的 AI 平台。

**请求参数：**

```json
{
  "apiKey": "your-api-key",
  "model": "glm-4.5-flash",
  "provider": "zhipu",
  "messages": [
    { "role": "user", "content": "你好" }
  ],
  "stream": true
}
```

**响应格式（SSE）：**

```
Content-Type: text/event-stream

data: {"content": "你好", "usage": null}
data: {"content": "！", "usage": {"prompt_tokens": 5, "completion_tokens": 2}}
data: [DONE]
```

**错误响应：**

```json
{
  "error": "API Key is required"
}
```

#### GET /sse

SSE 演示接口，逐字发送文本。

**请求参数：**

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| speed | number | 50 | 发送速度（毫秒/字） |
| text | string | 默认文本 | 自定义发送文本 |

**响应事件：**

```
event: connected
data: {"status": "connected", "connectionId": "1"}

data: {"char": "你", "index": 0, "total": 100}

event: done
data: {"status": "complete"}
```

#### POST /pause?id={connectionId}

暂停指定连接的输出。

#### POST /resume?id={connectionId}

恢复指定连接的输出。

## 8. 错误处理

### 8.1 错误类型

| 错误类型 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 网络错误 | 无网络连接 | 显示离线提示 + 自动重试 |
| API 错误 | API Key 无效/额度用尽 | 显示错误消息 |

## 9. 安全考虑

### 9.1 API Key 处理

- API Key 仅存储在浏览器本地存储
- 通过后端代理转发请求，避免前端直接调用 AI API
- 服务端不存储任何 API Key

### 9.2 XSS 防护

- 所有用户输入在渲染前进行 HTML 转义
- 代码块内容单独处理，避免注入

```javascript
function escapeHtml(text) {
  const div = document.createElement('div');
  div.textContent = text;
  return div.innerHTML;
}
```
