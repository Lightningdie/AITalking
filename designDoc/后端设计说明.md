# 后端设计说明

本文档描述 Node.js 后端（`server/`）各目录与核心文件的功能、职责与设计要点。与 [功能设计文档](./功能设计文档.md)、[API接口文档](./API接口文档.md) 配合使用。

---

## 1. 目录结构

```
server/
├── index.js          # 主入口：创建 HTTP 服务、注册路由与 404
├── config/           # 配置：API 平台、常量、MIME、统一导出
├── routes/           # 路由处理：静态、聊天代理、SSE 演示、暂停/继续
├── services/         # 业务服务：SSE 连接状态管理
└── utils/            # 工具：请求体解析、响应与 SSE 发送、CORS
```

---

## 2. 主入口 index.js

- **职责**：使用原生 `http.createServer` 创建服务，按 `pathname` 与 `method` 分发到对应路由；未匹配则 404。
- **路由顺序**：
  1. `OPTIONS` → `handleCORS(res)` 处理预检。
  2. 静态路由（`handleStaticRoutes`）：`/`、`/index.html`、`/css/*`、`/js/*`。
  3. `POST /api/chat` → `handleChatProxy`（AI 聊天代理）。
  4. `/sse` → `handleSSE`（SSE 打字机演示）。
  5. `POST /pause`、`POST /resume` → 暂停/继续控制。
  6. 其余 → 404。
- **设计要点**：无框架依赖，逻辑清晰；端口从 `config` 读取，启动时打印提示。

---

## 3. config/

### 3.1 api.config.js

- **职责**：各 AI 平台的连接配置。当前支持 `zhipu`（智谱）、`spark`（讯飞星火）。每项包含：`name`、`hostname`、`path`、`defaultModel`。聊天路由根据请求体中的 `provider` 取对应配置发起 HTTPS 请求。

### 3.2 constants.js

- **职责**：服务常量，如 `PORT`。供 index 与需要端口的地方使用。

### 3.3 mime.config.js

- **职责**：扩展名到 MIME 类型的映射，供静态文件响应时设置 `Content-Type`。

### 3.4 index.js

- **职责**：统一导出 config，便于其他模块 `require('./config')` 或按需引用。

---

## 4. routes/

### 4.1 chat.js

- **职责**：AI 聊天代理。接收前端 `POST /api/chat`，校验 `apiKey`、`messages`、`provider`；按 `api.config` 构建目标平台的请求体与请求选项；设置 SSE 响应头后向第三方 AI 发起 HTTPS 请求，将 API 的流式响应逐块转发给客户端（`data: {...}\n\n`）；客户端断开时 `req.on('close')` 里销毁请求。
- **核心函数**：
  - `handleChatProxy(req, res)`：入口；读 body、校验、构建请求、发起并转发流。
  - `validateChatParams(apiKey, messages, provider)`：返回错误字符串或 null。
  - `buildRequestBody(model, messages, stream, config)`：拼成平台需要的 JSON 体。
  - `buildRequestOptions(config, apiKey, requestBody)`：hostname、path、headers（含 Authorization）。
  - `createApiRequest(options, res)`：创建 `https.request`，处理 data/end/error，用 `sendSSEData` 写回前端；错误时写 `data: {"error": "..."}`。
- **设计要点**：不解析流内容业务含义，只做透明代理与错误透传；响应格式与 [API接口文档](./API接口文档.md) 一致。

### 4.2 static.js

- **职责**：静态文件服务。根据 pathname 映射到项目根目录下的 `index.html`、`css/*`、`js/*`，通过 `serveStaticFile` 读文件并设置 Content-Type；文件不存在则 404。
- **设计要点**：ROOT_DIR 为 `server` 的上一级，与主入口所在层级一致。

### 4.3 sse.js

- **职责**：SSE 打字机演示。用于演示 SSE 连接与推送，与 React 聊天前端的 `/api/chat` 流式接口无关；可按需阅读或用于调试 SSE。

### 4.4 control.js

- **职责**：暂停/继续控制。配合 `services/connection` 对 SSE 演示页的连接做 pause/resume，供演示或调试用；与 React 聊天业务无直接耦合。

### 4.5 index.js

- **职责**：统一导出各路由的 handle 函数，供主入口 require。

---

## 5. services/

### 5.1 connection.js

- **职责**：SSE 连接状态管理。维护一个 `Map` 存储连接 id 与状态对象；提供 `generateConnectionId`、`createConnection`、`getConnection`、`removeConnection`、`pauseConnection`、`resumeConnection`、`getConnectionCount`。被 routes/control 与 routes/sse 使用，用于演示页的暂停/继续与连接清理。
- **设计要点**：与 `/api/chat` 的代理流无关，仅服务于演示 SSE 的 path。

### 5.2 index.js

- 导出 connection 服务。

---

## 6. utils/

### 6.1 request.js

- **职责**：请求解析。`readBody(req)` 将 POST body 流式拼接后 `JSON.parse`，返回 Promise；`getQueryParam`、`getQueryParamInt` 从 URL 中取查询参数。聊天路由用 `readBody` 获取 apiKey、model、messages、stream、provider。

### 6.2 response.js

- **职责**：响应与 SSE 辅助。`jsonResponse(res, statusCode, data)` 写 JSON 并设置 CORS；`serveStaticFile(filePath, res)` 按 MIME 读文件并 pipe 到 res；`setSSEHeaders(res)` 设置 `text/event-stream` 等；`sendSSEData(res, data, event)` 写 `data: ...\n\n`；`handleCORS(res)` 处理 OPTIONS 预检。
- **设计要点**：所有对客户端的写操作集中在此，便于统一 CORS 与错误格式。

### 6.3 index.js

- 导出 utils，供 routes 与 index 使用。

---

## 7. 请求流小结（与前端对接）

```
前端 POST /api/chat (body: apiKey, model, provider, messages, stream)
     → index.js 分发到 handleChatProxy
     → readBody(req) 解析 body
     → validateChatParams → 失败则 jsonResponse(400, { error })
     → buildRequestBody + buildRequestOptions(api.config[provider])
     → setSSEHeaders(res)
     → https.request 向智谱/讯飞发起请求，body 为平台格式
     → API 流式返回 → createApiRequest 中 on('data') 用 sendSSEData 转发
     → 前端 fetch 读 ReadableStream，chatService 解析 data 行，useChat 更新 UI
```

静态资源、SSE 演示、pause/resume 仅服务于演示或调试，React 前端主要依赖 `/api/chat` 与静态资源（若部署时由同一服务提供前端构建产物，可在 static 中增加对 react-chat 构建目录的映射）。

## 8. 与设计文档的对应关系

- **功能设计文档**：多平台、流式/非流式、代码高亮、导出、Token、上下文等需求在后端的体现为「透明代理 + 统一错误与 SSE 格式」。
- **API 接口文档**：`/api/chat` 的请求字段、SSE 事件格式、错误码与 `chat.js`、`response.js` 的实现一一对应；扩展新平台时只需在 `api.config.js` 增加配置并在 `validateChatParams` 中允许新 provider。
