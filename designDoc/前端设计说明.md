# 前端设计说明

本文档描述 React 前端（`react-chat/src`）各目录与核心文件的功能、职责与设计要点。与 [功能设计文档](./功能设计文档.md)、[API接口文档](./API接口文档.md) 配合使用。

---

## 1. 目录结构

```
react-chat/src/
├── api/           # 请求层：封装与后端的 HTTP/SSE 调用
├── components/    # UI 组件：聊天容器、消息、侧栏、输入框等
├── hooks/         # 自定义 Hooks：对话状态、本地持久化
├── services/      # 业务服务：流式/非流式发送逻辑
├── styles/        # 样式：全局与代码高亮
├── types/         # 类型定义：消息、API、配置等
├── utils/         # 工具函数：消息构造、网络、Token 估算
├── App.tsx        # 根组件：组装 Sidebar + ChatContainer，注入 useChat
└── main.tsx       # 入口
```

---

## 2. 入口与根组件

### 2.1 main.tsx

- 挂载 React 根节点，引入全局样式。
- 无业务逻辑。

### 2.2 App.tsx

- **职责**：组装整体布局（背景效果、侧栏、聊天区），管理「与 UI 强相关」的本地状态。
- **状态**：`provider`、`apiKey`、`model`、`contextLength` 使用 `useLocalStorage` 持久化；`streamMode` 仅内存。
- **数据流**：将 `useChat` 的返回值（消息、状态、发送/取消/清空/导出等）分发给 `Sidebar` 与 `ChatContainer`；根据 `streamMode` 决定调用 `sendMessageStream` 或 `sendMessageNonStream`。
- **设计要点**：业务状态与发送逻辑集中在 `useChat`，App 只做桥接与布局。

## 3. components/ 组件

### 3.1 ChatContainer.tsx

- **职责**：聊天主区域容器。包含标题、流式/非流式切换、错误提示、消息列表滚动区、输入框。
- **核心逻辑**：
  - `displayMessages = messages + (streamingMessage ? [streamingMessage] : [])`，历史与当前流式消息分离展示。
  - 滚动：仅在用户处于底部附近时自动滚到底部（`userAtBottomRef` + `isNearBottom`），避免打断用户查看历史。
  - 根据 `status` 派生 `inputDisabled`、`showLoading`、`showCancel`。
- **依赖**：MessageList、InputBox；接收 `onSendMessage`、`onCancel`、`streamMode`/`onStreamModeChange` 等由 App 传入的 useChat 能力。

### 3.2 Sidebar.tsx

- **职责**：侧边栏。平台与模型选择、API Key 输入、上下文轮数、Token 统计、清空对话、导出 Markdown、网络/上下文预警。
- **数据**：`PROVIDERS` 写死智谱 / 讯飞星火的名称、模型列表、placeholder；`provider` 切换时自动带出该平台默认模型。
- **设计要点**：展示 `contextTokens`、`tokenWarningReached`、`contextTokenLimit`、`tokenWarningThreshold`，便于用户在做长对话前看到用量与预警。

### 3.3 MessageList.tsx

- **职责**：仅负责渲染消息列表；无滚动逻辑（滚动由父级 `messages-area` 的容器 + `useEffect` 控制）。
- **Props**：`messages: Message[]`、可选 `emptyContent`。将每条消息交给 `MessageItem`，并传入 `isStreaming`、`messageStatus`。

### 3.4 MessageItem.tsx

- **职责**：单条消息气泡的纯展示。根据 `role` 区分样式与头像；根据 `messageStatus` 显示「已中断」「请求失败」等提示；流式且无内容时显示 TypingDots。
- **设计要点**：不持有业务状态，不解析 Markdown/代码块，仅把 `content` 交给 `MessageContent`。

### 3.5 MessageContent.tsx

- **职责**：将消息正文从「纯文本 + Markdown」渲染为 React 节点。仅对**已闭合**的 ```...``` 代码块交给 `CodeBlock` 高亮，未闭合部分当普通文本，避免流式输出中途断语法导致报错。
- **解析**：`parseContent` 用 `CLOSED_CODE_BLOCK_REGEX` 拆出代码块与普通文本；`formatInlineText` 处理引用、无序/有序列表、段落等行级 Markdown。

### 3.6 CodeBlock.tsx

- **职责**：代码块展示与一键复制。使用 highlight.js 对已闭合的代码块做语法高亮；语言未知或异常时回退为纯文本并保留样式类。
- **设计要点**：仅接收「已闭合」的代码内容，避免流式未闭合片段触发 hljs 报错；复制成功后 2 秒内显示「已复制」。

### 3.7 InputBox.tsx

- **职责**：多行输入框 + 发送按钮。Enter 发送、Shift+Enter 换行；高度随内容自适应（有上限）。
- **设计要点**：禁用与 loading 状态由外部传入，组件只负责输入与提交 UI。

### 3.8 index.ts

- 统一导出各组件，供 App 等按需引用。

## 4. hooks/

### 4.1 useChat.ts

- **职责**：对话核心状态与流程。维护 `messages`、`streamingMessage`、`status`、`lastErrorMessage`、`isOffline`、`stats`；提供 `sendMessageStream`、`sendMessageNonStream`、`exportToMarkdown`、`cancel`、`clear`、`addError`；并计算 `contextTokens`、`tokenWarningReached`。
- **设计要点**：
  - **流式**：历史消息仅在「本轮流式完成或失败」后写入 `messages`；流式过程中只更新 `streamingMessage`，并用 `pendingStreamContentRef` + 节流（约 80ms）减少渲染频率。
  - **上下文**：按 `contextLength` 取最近 N 轮 user/assistant/system，再交给 `estimateMessagesTokens` 算 token；与 `contextTokenLimit`、`tokenWarningThreshold` 比较得到预警。
  - **取消**：使用 `AbortController`，cancel 时中止 fetch，并将当前流式消息标记为 `aborted` 或按错误处理。
  - **离线**：监听 `online`/`offline` 更新 `isOffline`；发送前由 api/client 的 request 中 `checkOnline()` 拦截并抛 `ApiError('OFFLINE', ...)`。
- **依赖**：`createMessage`、`checkOnline`、`estimateMessagesTokens`/`initTokenTokenizer`、`sendStream`/`sendNonStream`。

### 4.2 useLocalStorage.ts

- **职责**：将状态持久化到 localStorage。用法同 `useState`，读入时 `JSON.parse`，写入时 `JSON.stringify`；异常时静默回退到初始值。
- **用途**：App 中持久化 provider、apiKey、model、contextLength。

### 4.3 index.ts

- 导出 `useChat`、`useLocalStorage`。

## 5. api/

### 5.1 client.ts

- **职责**：统一 HTTP 请求入口。带重试的 `request(config)`（最多 3 次、递增延迟）；请求前 `checkOnline()`，断网直接抛 `ApiError('OFFLINE', ...)`；`AbortError` 不重试。`parseErrorResponse(response)` 将后端 JSON 错误体转为 `ApiError`，便于上层统一处理。
- **设计要点**：所有与后端的 fetch 都经此层，便于后续切换接口或错误策略。

### 5.2 chat.ts

- **职责**：对话接口封装。`requestChatStream` 返回 `Response`（流式），调用方自行读 body 解析 SSE；`requestChat` 为非流式，内部按 SSE 行解析后聚合 `content` 与 `usage` 返回。
- **设计要点**：流式/非流式与后端约定见 [API接口文档](./API接口文档.md)；此处只做 URL、body、headers 与错误解析，不包含「读流 + 回调」的业务逻辑（在 services/chatService 中）。

### 5.3 index.ts

- 导出 api 模块供外部使用。

---

## 6. services/

### 6.1 chatService.ts

- **职责**：流式/非流式发送的业务流程。
  - **sendStream**：调用 `requestChatStream`，用 `ReadableStream.getReader()` 读 body，按行解析 `data: {...}`，对 `content` 做累积并 `onChunk(fullContent)`，对 `usage` 做 `onUsage(usage)`；遇到 `parsed.error` 或 signal 中止时抛错；finally 中 cancel reader。
  - **sendNonStream**：调用 `requestChat`，直接返回 `{ content, usage }`。
- **设计要点**：与 API 层解耦——API 只负责请求与响应体访问，本层负责「如何解读 SSE 流」与回调时机；便于以后换 WebSocket 时只改本层。

### 6.2 index.ts

- 导出 chatService。

---

## 7. utils/

### 7.1 message.ts

- **职责**：消息工厂。`generateMessageId()` 生成唯一 id；`createMessage({ role, content, status?, id?, createdAt? })` 返回符合 `Message` 类型的数据结构，默认 `status: 'done'`、`createdAt: Date.now()`。

### 7.2 network.ts

- **职责**：`checkOnline()` 使用 `navigator.onLine`；`delay(ms)` 返回 Promise，用于重试间隔。

### 7.3 tokenEstimate.ts

- **职责**：Token 估算。可选接入 `gpt-tokenizer`（`initTokenTokenizer` 异步加载）；未接入或失败时用启发式（约 2.5 字符/token）。`estimateTokens(text)` 单段文本；`estimateMessagesTokens(messages)` 多条消息并加上每条 4 token 的格式开销。用于 useChat 的 `contextTokens` 与预警。

### 7.4 index.ts

- 按需导出上述工具。

## 8. types/

### 8.1 index.ts

- **职责**：全局对话与消息类型。`ChatStatus`、`MessageRole`、`MessageStatus`、`Message`、`UseChatConfig`、`UseChatReturn`、`TokenStats`；并 re-export `api` 中的请求/响应与 `ApiError`。

### 8.2 api.ts

- **职责**：API 层类型。`ChatMessagePayload`、`ChatRequestParams`、`UsagePayload`、`ChatChunkPayload`、`ChatResponse`；以及 `ApiError` 类（code + message），便于上层按 code 分支或统一展示。

## 10. 数据流小结

```
用户输入 → InputBox.onSend
         → App.handleSendMessage (按 streamMode 选 sendMessageStream / sendMessageNonStream)
         → useChat.sendMessageStream 或 sendMessageNonStream
         → chatService.sendStream / sendNonStream
         → api/chat.requestChatStream / requestChat + api/client.request
         → 后端 /api/chat

SSE 流 → chatService 解析 data → onChunk / onUsage
       → useChat 更新 streamingMessage / stats，节流渲染
       → 完成/失败后 messages 追加，streamingMessage 置空

UI：messages + streamingMessage → ChatContainer → MessageList → MessageItem → MessageContent (+ CodeBlock)
```

侧栏的 provider、apiKey、model、contextLength 等经 useLocalStorage 持久化后传入 useChat；Token 统计与预警由 useChat 的 contextTokens、tokenWarningReached 提供，Sidebar 只做展示与操作入口。
