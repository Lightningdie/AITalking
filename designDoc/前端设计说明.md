# 前端设计说明

本文档描述 React 前端（`react-chat/src`）各目录与核心文件的功能、职责与设计要点。与 [功能设计文档](./功能设计文档.md)、[API接口文档](./API接口文档.md) 配合使用。

---

## 1. 目录结构

```
react-chat/src/
├── api/              # 请求层：client（重试/错误）、chat（流式/非流式）
├── components/       # UI 组件：聊天容器、消息、侧栏（含会话列表）、输入框等
├── hooks/            # useChat、useLocalStorage、useSessions
├── services/         # chatService（SSE 解析）、modelService（统一模型协议）
├── styles/           # 全局与代码高亮样式
├── types/            # 消息、API、model 协议、Session 类型
├── utils/             # message、network、tokenEstimate、sessionStorage
├── App.tsx           # 根组件：useSessions + useChat 桥接，Sidebar + ChatContainer
└── main.tsx          # 入口
```

---

## 2. 入口与根组件

### 2.1 main.tsx

- 挂载 React 根节点，引入全局样式。
- 无业务逻辑。

### 2.2 App.tsx

- **职责**：组装整体布局（背景效果、侧栏、聊天区），桥接会话与对话状态。
- **状态**：`provider`、`apiKey`、`model`、`contextLength`、`includeSystemInContext` 使用 `useLocalStorage` 持久化；`streamMode` 仅内存。
- **会话桥接**：`useSessions()` 提供 `sessions`、`currentSessionId`、`currentSessionData`、`createSession`、`deleteSession`、`switchSession`、`saveCurrentSessionMessages`。将 `currentSessionId`、`currentSessionData?.messages` 作为 `sessionId`、`initialMessages` 传入 `useChat`，使切换会话时 useChat 重置消息。
- **持久化时机**：`useEffect` 在 `status` 非 requesting/streaming 时调用 `saveCurrentSessionMessages(messages)`，把当前消息写回当前会话。
- **数据流**：useChat 返回值分发给 Sidebar 与 ChatContainer；Sidebar 额外接收会话相关 props（sessions、currentSessionId、onCreateSession、onSwitchSession、onDeleteSession）及 `contextMessages`、`includeSystemInContext`。

## 3. components/ 组件

### 3.1 ChatContainer.tsx

- **职责**：聊天主区域容器。包含标题、流式/非流式切换（StreamToggle）、停止按钮、错误提示、消息列表滚动区、输入框；空状态展示 WelcomeMessage。
- **核心逻辑**：
  - `displayMessages = messages + (streamingMessage ? [streamingMessage] : [])`，历史与当前流式消息分离展示。
  - 滚动：仅在用户处于底部附近时自动滚到底部（`userAtBottomRef` + `isNearBottom`），避免打断用户查看历史。
  - 根据 `status` 派生 `inputDisabled`、`showLoading`、`showCancel`。
  - 向 MessageList 传入 `virtualThreshold={50}`（`MESSAGE_VIRTUAL_THRESHOLD`），超过 50 条时只渲染最近 50 条并显示「上方还有 X 条」。
- **依赖**：MessageList、InputBox；接收 `onSendMessage`、`onCancel`、`streamMode`/`onStreamModeChange` 等由 App 传入的 useChat 能力。

### 3.2 Sidebar.tsx

- **职责**：侧边栏。会话列表（新建/切换/删除）、平台与模型选择、API Key 输入、上下文轮数、是否包含 system 消息、Token 统计、上下文 Token 估算与预警、当前上下文预览（将发给模型的 N 条）、清空对话、导出 Markdown。
- **数据**：`PROVIDERS` 写死智谱 / 讯飞星火的名称、模型列表、placeholder；`provider` 切换时自动带出该平台默认模型。
- **会话区**：当传入 `onCreateSession`、`onSwitchSession` 时渲染 `session-list`；列表项展示 `sessions[].title`，当前项高亮 `currentSessionId`；每项可点切换或点删除调用 `onDeleteSession(s.id)`。
- **上下文预览**：`context-preview` 展示 `contextMessages` 条数及每条 role + 内容摘要（前 50 字），并提供「一键清空上下文」按钮（调用 `onClear`）。
- **设计要点**：展示 `contextTokens`、`tokenWarningReached`、`contextTokenLimit`、`tokenWarningThreshold`；可选「上下文包含 system 消息」复选框绑定 `includeSystemInContext`、`onIncludeSystemInContextChange`。

### 3.3 MessageList.tsx

- **职责**：渲染消息列表；无滚动逻辑（滚动由父级 `messages-area` 的容器 + `useEffect` 控制）。支持虚拟化：超过 `virtualThreshold` 条时只渲染最近 N 条。
- **Props**：`messages: Message[]`、可选 `emptyContent`、`virtualThreshold?: number`（0 表示不限制）。当 `messages.length > virtualThreshold > 0` 时，`visibleMessages = messages.slice(-virtualThreshold)`，顶部显示「上方还有 X 条消息，仅展示最近 N 条」。
- **实现**：将 `visibleMessages` 交给 `MessageItem`，并传入 `isStreaming`、`messageStatus`。

### 3.4 MessageItem.tsx

- **职责**：单条消息气泡的纯展示。根据 `role` 区分样式与头像；根据 `messageStatus` 显示「已中断」「请求失败」等提示；流式且无内容时显示 TypingDots。
- **设计要点**：不持有业务状态，不解析 Markdown/代码块，仅把 `content` 交给 `MessageContent`。

### 3.5 MessageContent.tsx

- **职责**：将消息正文从「纯文本 + Markdown」渲染为 React 节点。仅对**已闭合**的 \`\`\`...\`\`\` 代码块交给 `CodeBlock` 高亮，未闭合部分当普通文本，避免流式输出中途断语法导致报错。
- **块级解析（formatInlineText）**：按行扫描，维护 blockquote、ul、ol、task、paragraph 缓冲区；识别标题（# 1–6）、水平线（---/***/___）、表格（|...|）、引用（> ）、任务列表（- [ ] / - [x]）、无序/有序列表，先 flush 再切换类型。表格由 `parseTableLines` 解析表头与数据行，输出 `<table>`。
- **行内解析（formatLine / parseSegmentWithLinks）**：行内用 \`...\` 切段后，段内解析链接 `[text](url)`、图片 `![alt](url)`（仅允许 http(s)、/、#、mailto:）；其余交给 `formatInlineBoldItalic` 处理 **粗体**、*斜体*、~~删除线~~。
- **设计要点**：链接与图片做安全协议校验，避免 `javascript:` 等；表格与任务列表有独立 flush 逻辑，与引用/列表/段落互斥。

### 3.6 CodeBlock.tsx

- **职责**：代码块展示与一键复制。使用 highlight.js 对已闭合的代码块做语法高亮；语言未知或异常时回退为纯文本并保留样式类。
- **设计要点**：仅接收「已闭合」的代码内容，避免流式未闭合片段触发 hljs 报错；复制成功后 2 秒内显示「已复制」。

### 3.7 InputBox.tsx

- **职责**：多行输入框 + 发送按钮。Enter 发送、Shift+Enter 换行；高度随内容自适应（有上限）。
- **设计要点**：禁用与 loading 状态由外部传入，组件只负责输入与提交 UI。

### 3.8 index.ts

- 统一导出各组件，供 App 等按需引用。

## 4. hooks/

### 4.1 useChat.ts

- **职责**：对话核心状态与流程。维护 `messages`、`streamingMessage`、`status`、`lastErrorMessage`、`isOffline`、`stats`；提供 `sendMessageStream`、`sendMessageNonStream`、`exportToMarkdown`、`cancel`、`clear`、`addError`；并计算 `contextTokens`、`tokenWarningReached`、`contextMessages`（当前会发给模型的上下文，只读，供侧栏预览）。
- **配置**：支持 `sessionId`、`initialMessages`（切换会话时由 App 注入）；`includeSystemInContext`（默认 true，为 false 时上下文过滤掉 system 消息）。
- **设计要点**：
  - **会话联动**：当 `sessionId` 变化时，重置 `messages` 为 `initialMessages`，清空 `streamingMessage`、`status`、`lastErrorMessage`。
  - **流式**：历史消息仅在「本轮流式完成或失败」后写入 `messages`；流式过程中只更新 `streamingMessage`，并用 `pendingStreamContentRef` + 节流（约 80ms）减少渲染频率。
  - **上下文**：按 `contextLength` 与 `includeSystemInContext` 过滤后取最近 N 轮，再交给 `estimateMessagesTokens` 算 token；与 `contextTokenLimit`、`tokenWarningThreshold` 比较得到预警。
  - **模型调用**：不直接调用 chatService，而是调用 `requestModel`（modelService），传入 `modelId: \`${provider}:${model}\``、`messages`、`stream` 及 onChunk/onComplete/onError。
  - **取消**：使用 `AbortController`，cancel 时中止请求，并将当前流式消息标记为 `aborted` 或按错误处理。
  - **离线**：监听 `online`/`offline` 更新 `isOffline`；发送前由 api/client 的 request 中 `checkOnline()` 拦截并抛 `ApiError('OFFLINE', ...)`。
- **依赖**：`createMessage`、`checkOnline`、`estimateMessagesTokens`/`initTokenTokenizer`、`requestModel`（modelService）。

### 4.2 useLocalStorage.ts

- **职责**：将状态持久化到 localStorage。用法同 `useState`，读入时 `JSON.parse`，写入时 `JSON.stringify`；异常时静默回退到初始值。
- **用途**：App 中持久化 provider、apiKey、model、contextLength、includeSystemInContext。

### 4.3 useSessions.ts

- **职责**：会话列表与当前会话状态。维护 `sessions`（SessionMeta[]）、`currentSessionId`、`currentSessionData`（SessionData | null）；提供 `createSession`（新建并切换）、`deleteSession`、`switchSession`、`saveCurrentSessionMessages`、`refreshSessionList`。
- **实现要点**：底层调用 `utils/sessionStorage` 的 getSessionList、getCurrentSessionId、setCurrentSessionId、getSession、saveSession、createSession、deleteSession。切换会话时 `setCurrentSessionId` 写回 localStorage，并 `setCurrentSessionData(getSession(id))`；删除当前会话后自动切到列表第一项或新建会话。
- **与 useChat 配合**：App 将 `currentSessionId`、`currentSessionData?.messages` 作为 useChat 的 `sessionId`、`initialMessages`，并在非请求中时用 `saveCurrentSessionMessages(messages)` 写回当前会话。

### 4.4 index.ts

- 导出 `useChat`、`useLocalStorage`、`useSessions` 及相关类型。

## 5. api/

### 5.1 client.ts

- **职责**：统一 HTTP 请求入口。带重试的 `request(config)`（最多 3 次、递增延迟）；请求前 `checkOnline()`，断网直接抛 `ApiError('OFFLINE', ...)`；`AbortError` 不重试。`parseErrorResponse(response)` 将后端 JSON 错误体转为 `ApiError`，便于上层统一处理。
- **设计要点**：所有与后端的 fetch 都经此层，便于后续切换接口或错误策略。

### 5.2 chat.ts

- **职责**：对话接口封装。`requestChatStream` 返回 `Response`（流式），调用方自行读 body 解析 SSE；`requestChat` 为非流式，内部按 SSE 行解析后聚合 `content` 与 `usage` 返回。
- **设计要点**：流式/非流式与后端约定见 [API接口文档](./API接口文档.md)；此处只做 URL、body、headers 与错误解析，不包含「读流 + 回调」的业务逻辑（在 services/chatService 中）。

### 5.3 index.ts

- 导出 api 模块供外部使用。

## 6. services/

### 6.1 chatService.ts

- **职责**：流式/非流式发送的业务流程。
  - **sendStream**：调用 `requestChatStream`，用 `ReadableStream.getReader()` 读 body，按行解析 `data: {...}`，对 `content` 做累积并 `onChunk(fullContent)`，对 `usage` 做 `onUsage(usage)`；遇到 `parsed.error` 或 signal 中止时抛错；finally 中 cancel reader。
  - **sendNonStream**：调用 `requestChat`，直接返回 `{ content, usage }`。
- **设计要点**：与 API 层解耦——API 只负责请求与响应体访问，本层负责「如何解读 SSE 流」与回调时机；便于以后换 WebSocket 时只改本层。仅被 modelService 调用，UI/useChat 不直接依赖。

### 6.2 modelService.ts

- **职责**：统一模型协议入口。UI 与 useChat 只依赖 `ModelRequestParams` + `ModelCallbacks`，不直接接触 fetch 或 api/chat。
- **实现**：`requestModel(params, callbacks, { signal, apiKey })`。将 `params.modelId` 按 `:` 解析为 `provider`、`model`，组装 `ChatRequestParams`；流式时调用 `sendStream` 并在结束时 `onComplete(lastUsage)`，非流式时调用 `sendNonStream` 后 `onChunk(content)`、`onComplete(usage)`；异常时 `onError(err)` 并 rethrow。
- **设计要点**：唯一调用 chatService 的模块；便于后续切换为其它 SDK 或接口时只改本层。

### 6.3 index.ts

- 导出 chatService、modelService 及相关类型。

## 7. utils/

### 7.1 message.ts

- **职责**：消息工厂。`generateMessageId()` 生成唯一 id；`createMessage({ role, content, status?, id?, createdAt? })` 返回符合 `Message` 类型的数据结构，默认 `status: 'done'`、`createdAt: Date.now()`。

### 7.2 network.ts

- **职责**：`checkOnline()` 使用 `navigator.onLine`；`delay(ms)` 返回 Promise，用于重试间隔。

### 7.3 tokenEstimate.ts

- **职责**：Token 估算。可选接入 `gpt-tokenizer`（`initTokenTokenizer` 异步加载）；未接入或失败时用启发式（约 2.5 字符/token）。`estimateTokens(text)` 单段文本；`estimateMessagesTokens(messages)` 多条消息并加上每条 4 token 的格式开销。用于 useChat 的 `contextTokens` 与预警。

### 7.4 sessionStorage.ts

- **职责**：按会话 ID 使用 localStorage 存储会话数据；会话列表单独存 `chat_session_list`（`{ currentId, ids }`），单会话存 `chat_session_{id}`（SessionData）。
- **接口**：`getSessionList()` 返回 SessionMeta[]（按 updatedAt 倒序）；`getCurrentSessionId`、`setCurrentSessionId`；`getSession(id)`、`saveSession(id, data)`（标题可由首条用户消息前 28 字推导）；`createSession()` 新建并设为当前；`deleteSession(id)` 删除并若为当前则切到列表首项或新建。`generateSessionId()` 供内部与测试使用。

### 7.5 index.ts

- 按需导出 message、network、tokenEstimate、sessionStorage 等。

## 10. 数据流小结

**发送与流式：**

```
用户输入 → InputBox.onSend
         → App.handleSendMessage (按 streamMode 选 sendMessageStream / sendMessageNonStream)
         → useChat → requestModel (modelService)
         → chatService.sendStream / sendNonStream
         → api/chat.requestChatStream / requestChat + api/client.request
         → 后端 /api/chat

SSE 流 → chatService 解析 data → onChunk / onUsage
       → useChat 更新 streamingMessage / stats，节流渲染
       → 完成/失败后 messages 追加，streamingMessage 置空

UI：messages + streamingMessage → ChatContainer → MessageList（可选 virtualThreshold）→ MessageItem → MessageContent (+ CodeBlock)
```

**会话与持久化：**

```
useSessions 提供 sessions、currentSessionId、currentSessionData
         → App 将 currentSessionId、currentSessionData?.messages 传入 useChat(sessionId, initialMessages)
         → 用户 switchSession(id) → setCurrentSessionId(id) → useChat 的 sessionId 变化 → messages 重置为 initialMessages

非 requesting/streaming 时 App 的 useEffect 调用 saveCurrentSessionMessages(messages)
         → sessionStorage.saveSession(currentSessionId, { messages, ... }) → localStorage
```

侧栏的 provider、apiKey、model、contextLength、includeSystemInContext 经 useLocalStorage 持久化后传入 useChat；Token 统计与预警由 useChat 的 contextTokens、tokenWarningReached 提供；contextMessages 供 Sidebar 的「当前上下文预览」展示；Sidebar 的会话区由 useSessions 的 sessions、currentSessionId、createSession、switchSession、deleteSession 驱动。
